# 真实模型评测基线

简体中文 | [English](README.en.md)

CI 的离线门禁（`python -m app.evals run --gate`）只检查流水线和服务端判定：脚本化策略驱动真实的工具、假设检验和校验，不调用模型，因此不衡量模型质量。模型质量用 `--suite live` 对真实模型单独测量，结果归档在这里。

## 2026-11-03 · 提示词 3.0 · 语法 3.0

[运行结果](2026-11-03-live/)：[Sonnet](2026-11-03-live/live-sonnet.json)、[Haiku](2026-11-03-live/live-haiku.json)、[逐例对比](2026-11-03-live/compare.md)。文件里只有指标、报告文本和步骤摘要，不含凭证和接口地址。

```bash
python -m app.evals run --suite live --model-config <id> --repeat 3 --max-tokens <上限> --out <文件>
```

- 24 个用例 × 3 次。Anthropic Messages 协议，模型自身默认思考设置，输出上限 16,000，请求超时 45 秒（模型配置默认值）。
- Sonnet 配置的审稿模型为 Haiku；Haiku 配置没有审稿模型。
- 两个模型并行运行在隔离的 Compose 实例上，未启用 LLM 裁判，文本指标为启发式打分。
- **Haiku 未跑完**：在 600 万 token 的上限前停止，完成 53/72 次（完整 2 轮，第 3 轮 5 例），波动只按完整的 2 轮计算。
- `forbidden_hits` 已按修正后的规则重算：说明缺少哪类数据的句子（如“当前没有流量和广告数据，需商家自行核对”）不再计入。Sonnet 的值从 7 降为 1，剩下的 1 次是一条“检查广告投放安排”的建议；JSON 中保存的仍是旧值。

### 结论

1. **默认推荐 Sonnet。** 它通过率 93%、原因召回 80%，三轮波动都在 2.5 个百分点以内；成本约每份报告 $0.20–0.23，延迟中位数约 65 秒。Haiku 便宜约 15 倍，但只有一半报告能通过校验，问答类全部失败，目前不适合作为主模型，可以继续用作审稿模型。
2. **剩余失败几乎都是“修复预算耗尽”。** 首稿的语法问题以 `PATH_NOT_ALLOWED` 和 `UNBOUND_NUMBER_OR_CLAIM` 为主，两次补丁后仍有残留。英文用例 `refund_spike_en` 在 Sonnet 上 3 次失败 2 次，是最明确的改进对象。下一步应在修复步骤里记录被拒绝的路径，判断这些是语法白名单的缺口，还是提示词没讲清楚。
3. **超时来自 45 秒的默认请求超时。** 输出上限提高到 16,000（自适应思考计入其中）以后，长的写作调用会超过 45 秒；Haiku 的 5 次超时都发生在写作调用上。3.0.0 已把新配置的默认值提高到 120 秒，已有配置需要手动调整。
4. **方向一致性检查暂不升级为硬性校验。** Sonnet 72 次运行共有 8 次方向提示，补丁通常能修掉；在 44 条标注句子上，这项检查的精度和召回都是 81%（`python -m app.evals direction`），误报集中在否定句。精度不足以把它作为阻断条件。
5. **缓存命中约 37%。** 计划、写作、补丁使用不同的输出格式，每次切换格式都会建立新的缓存条目；要进一步降低成本，得统一这几步的请求前缀。

### TheLook 实测

同一版本在 TheLook 数据（2024-01-01 至 01-07）上用 Sonnet 生成了一份周报：确定性指标与[复现文档](../TECHNICAL.md#示例数据与复现)一致（净销售额 USD 116,360.35，1,607 单）。模型提出 4 条假设，服务端检验均为“数据支持”；服务端另提出 2 条，均被排除，其中一条是“退款占比变化来自单品退款率”，检验结果显示主要来自商品结构（+0.98 个百分点对 +0.12 个百分点）。审稿提出了问题，但据此生成的补丁没有减少问题，因此保留原稿。

按 `scripts/agent_latency.py` 统计，含 1 次追问共 9 次模型调用、98.7 秒：写作占 54%，修复 14%，计划 13%，工具 11%，审稿 7%；服务端假设检验只用了约 40 毫秒。缓存命中率为输入的 38.5%。

这次实测发现并修复了两处“估算”标注问题：已确认的数值不再被标为估算，假设句末也不再重复“（估算）”。
